# SALSA vs. Jev on JevBench — GPU results (2026-10-08)

SALSA reads a typed decision (yes/no, one-of-N choice, ordinal score) from a frozen LLM
in **one forward pass**. Each option is mapped to a single token, and the answer
distribution is the softmax over those tokens' logits at the answer position. There is
no fine-tuning, no option rotation and no calibration fit. The decision API is
TypeSafe's `/v1/systemone`, which JevBench's own `typesafe` adapter calls.

This report runs the repo's SALSA server on **4× NVIDIA B200**. It sets the
results beside Jev 1.13.0 and the published JevBench systems, in the layouts of the two
comparable studies:

- **LLM2Jev** (github.com/Yinsongxu/LLM2Jev): a frozen LLM, one yes/no prefill per option.
- **AnyJev** (arXiv 2610.00831): a frozen LLM with one joint prefill, plus label-prior
  and rotation corrections.

## Summary

- **Accuracy: Qwen3.8-27B + SALSA matches Jev.** It scores **87.4%** on the 231 public
  items, against Jev 1.13.0's 86.6%. The difference is +0.9 pt (95% CI −3.0 to +4.3,
  McNemar p = 0.82), a statistical tie. It is level with the other Qwen3.8-27B systems on
  the board (86.1–87.0%), and well above LLM2Jev (76.2%, Qwen3.5-4B).
- **Against AnyJev's protocol (213 items), SALSA's raw readout scores 0.878.** That is
  above every model AnyJev reports, raw or debiased (best: Qwen3-32B at 0.798 / 0.789).
  Its ECE of 0.052, with no calibration fit, is below every ECE AnyJev reports, including
  the temperature-fitted ones (best 0.085).
- **Latency, Qwen on one B200, serial on localhost:** P50 **34 ms** and P95 **155 ms**,
  against Jev's 652 / 722 ms (19× lower at P50, 4.7× at P95). Jev's figure was measured
  over the internet, so this is not like-for-like. LLM2Jev reports 48 / 346 ms on unstated hardware.
- **Throughput:** 22 decisions/s per B200 serially; **273 decisions/s** at concurrency 64
  across 4 replicas (194k prompt tokens/s). AnyJev reports 16.7–37.2 decisions/s on one
  H100 for its 18-option task.
- **Run time:** the 231-decision serial benchmark takes **16 s**. Server start takes 4–6 min.
- **Repeatability:** two GPU runs gave identical answers on 231/231 items.

## 1. Setup

| | Qwen3.8-27B |
|---|---|
| Architecture | dense, 27B (Gated-DeltaNet + attention hybrid) |
| Weights served | bf16 |
| Engine | vLLM 0.31.0, torch 2.13.0+cu130, driver 580.173.02 |
| Layout on 4 GPUs | 4 replicas, 1 B200 each (DP=4, TP=1) |
| Output head | fp32 (`head_dtype=float32`) |
| Prompt | Qwen chat template, thinking off, ends at `<ANSWER>\n` |

**Protocol.**

- **Benchmark run:** JevBench's own CLI and `typesafe` adapter, serial (one request in
  flight), no retries. The data is the JevBench public set, 231 items (easy 48,
  standard/original 72, hard 111), pinned at commit `bb05a33` and verified against the
  benchmark's SHA-256 manifest.
- **Warm-up:** 16 untimed decisions before the timed run.
- **Order-flip:** every choice item asked again with its options reversed.
- **Load test:** a closed-loop concurrency sweep from 1 to 128.

**How published systems are scored.** They come from JevBench's per-item outcomes
(`results/v1.2/jevbench-v1.2-per-task.json`) with the same scorer, so every row is
computed one way. Numbers that exist only in the LLM2Jev and AnyJev papers are labelled
*as reported*. Tables are generated by `scripts/jev_compare.py`.

**Two protocols are shown:**

- **LLM2Jev / JevBench:** all 231 items, accuracy with failures counted wrong, serial
  latency P50/P95 over every decision.
- **AnyJev:** the 213 items whose expected answer is an option (the 18 `score` items
  skipped, which reproduces its 48/60/105 tier counts); ECE over 15 equal-mass bins;
  paired bootstrap 95% CIs (2,000 resamples); cov@5%; order-flip rate.

## 3b. Other frozen-LLM decision readers on the same 231 items

source. Readouts, hardware and calibration definitions differ, so read the accuracy
columns as the comparable part.

Three projects have near-identical names:
- **LLM2Jev** is the repository github.com/Yinsongxu/LLM2Jev.
- **LLM-as-Jev** is the paper arXiv 2610.02076 (its v1 was titled "LLM2Jev").

## 8. What is and is not comparable

- **Item sets.** JevBench public items only. The held-out items and the 146-item judge
  tier are not available, so none of this is an official JevBench Score. AnyJev also uses
  public items only (213); LLM2Jev uses all 231.
- **Jev's accuracy.** LLM2Jev quotes 85.1% for Jev 1.13.0. JevBench's per-item outcomes
  give 200/231 = 86.6%, and they reproduce every other LLM2Jev row exactly.
- **Readouts.** SALSA here is AnyJev's *raw* level: one order, no label-prior division,
  no rotations, no temperature. AnyJev's rotations would cost up to K prefills per
  decision.
- **Hardware.**
  - SALSA: B200, localhost.
  - AnyJev: H100 NVL, vLLM 0.7.0, timed on an 18-option routing task, not JevBench.
  - LLM2Jev: hardware not stated.
  - Jev and the board systems: measured over the internet.

## 9. Reproduce

```bash
./run_jev.sh setup                                    # venv, JevBench checkout, CUDA 13.0 JIT toolkit
GPUS=0,1,2,3 DP=4 TP=1 ./run_jev.sh flow              # Qwen3.8-27B
python scripts/jev_compare.py --run "label|conditions|logs/jev/<run>" ... --out tables.md
```

Every run directory under `logs/jev/` holds:

- `results.jsonl` and `raw/`: per-item answers and raw API responses;
- `manifest.json` and `env.json`: run settings, versions and hardware;
- `load.json`: the concurrency sweep;
- `orderflip.json` and `timing.json`: order-flip results and phase timings;
- `vllm.log`.

## 10. Training data

AnyJev trains nothing and releases no training set. The **BEV Decision Mix** dataset it
evaluates on (`avbiswas/bev-decision`, Hugging Face) does ship train splits:

| config | rows (train + test) | note |
|---|---:|---|
| `default` | 150,000 | AnyJev's test split is 46,320 of these |
| `hard_50k` | 50,000 | |
| `numeric_temporal` | 19,806 | targets SALSA's weakest JevBench family (dates and arithmetic, 5/15) |
| `all` | 276,188 | |

It is the natural candidate for a SALSA fine-tune. Two checks come first: its licence is
listed as unknown, and its overlap with JevBench items needs measuring before any result
on JevBench could be trusted.
